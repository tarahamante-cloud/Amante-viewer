# Build evidence and limitations

## Unchanged upstream baseline

- Exact commit: `d555fb677004bee8fd9e7f12b0e33a8978e77d4c`.
- Replit's initial Rust 1.88 toolchain was too old for the locked dependencies.
- Installed Rust 1.99.1 and the required native Linux development libraries.
- Rustup's compiler conflicted with Replit's `LD_AUDIT` loader. Invoking only
  the child compiler/build process with `env -u LD_AUDIT` resolved that issue.
- **Succeeded before application edits:**
  `env -u LD_AUDIT CARGO_BUILD_JOBS=2 cargo build --profile ci --locked -p aurora-viewer`.
- Baseline `--version` succeeded without a window/network:
  `Aurora Viewer 0.0.0+2.g3631f4aef`.
- The version's Git revision came from the enclosing Replit project after
  nested-repository import. It is not the upstream baseline identifier.
  The upstream commit/blob identities are recorded separately in the inventory.

## What Replit can verify here

Editing, dependency inspection, source comparison, compilation and offline
native regression tests are possible. The native Vulkan viewer has not been
replaced by the unrelated starter web/API artifacts.

No `/dev/dri` GPU device was exposed during the environment check. This session
has not demonstrated a working desktop Vulkan/display path. A browser screenshot
or a running API server would not prove this native application works.

Use `bash scripts/amante-dev.sh check|build|test|version` from the workspace
root. `demo` requires an actual desktop display and working Vulkan adapter.
No managed web workflow is presented as the native viewer.

## Distribution status

This is an in-progress source fork, not a security-validated or runtime-certified
release. The owner approved a public native-source upload to
<https://github.com/tarahamante-cloud/Amante-viewer>. Its root workflow builds
a development ZIP and records separate package and test evidence. It does not
publish a release, sign code, or activate updates. A running workflow is not
proof that a downloadable or working package exists.
